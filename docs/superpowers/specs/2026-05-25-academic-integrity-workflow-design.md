# 生命科学学院学术论文防造假全生命周期 Workflow — 设计文档

## Context

2026 年 4-5 月，退学博士科普博主"耿同学"实名举报多所高校（同济大学、南开大学、中山大学、上海大学）杰青学者论文造假，涉及图像拼接、数据篡改、样本量虚报等问题。同济大学已免去涉事院长职务并解聘第一作者。耿同学抖音粉丝从 132.7 万涨至 201.5 万，声称手中仍有未公开的杰青造假素材。

**核心教训：** 论文发表前缺乏学院层面的可追溯审查机制，出事后原始数据"找不到"、"硬盘坏了"，学院管理层无法自证尽责。

**本文档定位：** 从生命科学学院院长的视角，设计一套可落地的全生命周期防造假 Workflow。不做官样文章，每一条都能直接执行。

**设计原则：**
- 机器扫雷，人工只看红灯
- 降低操作摩擦力，不增加师生无意义负担
- 每一步都留下不可篡改的审查痕迹
- 数据冷冻留底，确保五年后查得清、说得明

---

## 四阶段时间轴总览

| 阶段 | 时间 | 谁执行 | 核心逻辑 |
|---|---|---|---|
| Phase 1 · 日常数据管理 | 持续进行 | 学生 + PI | 降低造假动机——每一步操作都有痕迹，造假成本极高 |
| Phase 2 · 撰写前预审 | 投稿/送审前 2-4 周 | 学生自查 + PI 签字 | 数据进论文之前先过筛，问题在这一层拦截成本最低 |
| Phase 3 · 终审关卡 | 送审/答辩前 1 周 | 学术诚信委员会 | 学院最后一关，问题论文出不了门 |
| Phase 4 · 舆情应急响应 | 舆情触发时 | 院长 + 党委书记 + 委员会 | 用冷冻档案说话，不捂盖子，第一时间与造假者切割 |

## 学生保障与学院名声（跨阶段通用）

以下机制贯穿四个 Phase。核心逻辑：**学生因 PI 胁迫而被迫参与造假，最终背锅的是学生，但舆论火力集中的是"学院包庇导师"**——学生保护不是学生福利，是学院名声防火墙。

### 新生入学培训与《学术诚信知情书》

**入学时（注册后 1 个月内）：** 学院统一组织 2 小时 Workflow 培训 + 发放《学术诚信知情书》，学生 + PI 双方签字存档。知情书明确：学生服从 PI 违规指令不承担学术不端责任、有权通过党委书记通道实名举报、正常毕业不受学术不端案件牵连。**每年秋季更新培训**（1 小时，覆盖 Workflow 更新 + 上一年度案例）。

### 毕业时间线保障

Phase 2 + 3 大约需要 3-5 周。学院教务每学期发布倒推时间表，预留审查窗口。若因非学生过错（委员会延期、PI 未及时签字）错过送审 → 协调研究生院延长截止日期 2 周。若论文因他人问题被冻结而非学生本人问题 → 学生可剥离数据单独撰写学位论文。鼓励论文初稿完成前 6-8 周启动 Phase 2，早启动者优先排期。

### 费用承担原则

所有防造假审查的直接成本（NAS、ImageTwin、GPTZero、ELN、GitLab、区块链存证）由学院承担，不转嫁给课题组或学生。**名声逻辑：** 审查费用如果让学生自己出，外界会质疑"学院让学生在自费证明清白"——这本身就是名声风险。学院出钱，审查才独立，对外才有公信力。

## Phase 1 · 日常实验数据管理

**核心理念：** 宽进严出，降低操作摩擦力。用机器代替人工，从"日清"改为"节点清"。

### 1.1 电子实验记录本 (ELN) — 允许脏数据

**痛点：** 做实验当天强行回忆并排版录入不现实。手套上的速记比事后整理更真实。

**工具：** Benchling（免费版）/ LabArchives / RSpace

**操作：**
- 允许拍照上传纸质草稿、手套速记等"脏数据"作为原始凭证
- 取消 48 小时死线，改为"每周五下班前"或"组会前"集中整理上传本周核心数据
- 日常跑废的体系不用详细录，产出可用结果的那次实验必须补齐试剂批号和操作步骤
- 每季度 PI 抽查课题组 ELN，学院随机抽 10% 检查完整性

### 1.2 图像与结果归档 — 机器静默同步

**痛点：** 大半夜做完 WB 还要手动算哈希传服务器，反人性、易遗漏。

**工具：** 坚果云 / Synology Drive / NextCloud（部署于公共仪器电脑后台）

**操作：**
- 公共仪器（凝胶成像仪、显微镜）后台部署同步盘客户端
- 学生点保存，仪器端自动将原始格式（TIFF/CZI/ND2）静默同步至学院 NAS 个人文件夹
- 服务器端自动生成只读备份，学生无删除/覆盖权限
- 写论文用图时，只需确保 NAS 备份中有对应的未被修改的原图

**NAS 防篡改方案：**
- Drop Zone（写入区）：仪器端仅可追加新文件，不可删除/覆盖/重命名
- 定时搬移脚本（每 5 分钟）：将文件从 Drop Zone 移至 Archive（只读归档区）
- Archive：全员只读，按 课题组/仪器/日期 自动分类，仅管理员可操作
- NAS 快照：每天自动打不可变快照
- 实现：Synology NAS（推荐，零代码）/ MinIO（WORM 锁）/ 坚果云团队版

### 1.3 代码与数据管理 — 结果驱动，不审过程

**痛点：** 生信分析调参是黑洞，强制每次微调都 commit 毫无意义。

**工具：** Git（学院 GitLab 实例）

**操作：**
- 平时怎么写不管。但当生成用于组会汇报/论文的图表时，必须将该图 + 最终版代码 + 清洗后数据一起打包存档
- 提交物：代码 + sessionInfo() / renv.lock（锁死 R 包版本）+ requirements.txt
- 只审查最终代码能不能一键复现这张图，不审查中间试错过程

### 1.4 样本入库 — 分级管理

**操作：**
- 高优样本（临床血清、拭子等核心结论相关）：双人核对签字，数量精确
- 大批量样本（野外采集标本）：预制二维码冻存管，批量扫码入盒，系统自动生成含时间戳的清单。重点只核对总数和采集地点

## Phase 2 · 撰写前数据预审

**核心理念：** 软件扫雷 + PI 定性。数据进论文之前先过筛，问题在这一层拦截成本最低。

### 2.1 图像完整性自查

**工具：**
- Forensically（免费在线）—— 学生自扫底线，ELA + 克隆检测 + 噪声分析
- ImageTwin / Proofig（收费）—— 学院层面批量扫描
- Fiji/ImageJ 脚本 —— 批量提取 EXIF 元数据

**流程：**
1. 学生用 Forensically 自扫全部图片，提交报告截图
2. 学院用 ImageTwin 批量扫拟送审论文
3. 假阳性豁免：学生可对任何飘红区域写一句批注（如"统一基线对照"）—— 软件扫雷，PI 定性
4. 元数据兜底：Fiji 批量提取 EXIF，校验设备型号、拍摄时间、曝光参数。元数据缺失或与仪器不匹配 → 标记可疑
5. 哈希比对：论文图片 ↔ NAS 原始文件路径 ↔ SHA-256 一致

### 2.2 统计结果复现 — 截断式复现，不从头跑

**关键定义：** 不要求从原始 Fastq/FASTQ 文件开始从头跑全流程。TCGA 大队列联合分析或单细胞聚类跑一遍需要几十小时甚至 GPU 集群——在毕业季根本不可能完成。

**复现深度界定：**
- 学生提交"中间态清洗数据"（Clean Data）作为复现起点
- 例如：TCGA 临床信息经 R 脚本提取后的结构化表、标准化后的表达矩阵
- 系统只负责跑最后一步——生成 Table 1 基线表、生存曲线、核心统计检验的代码
- 这部分通常几分钟就能跑完并比对结果

**判定标准不变：**
- 代码跑不出论文数字 → 退回重做
- 代码跑出结果与论文不符 → 启动调查
- 检测到无注释的数据剔除 → 必须提供书面理由

### 2.3 样本量溯源

**三方交叉核对：** ELN 入库记录 vs 分析代码纳入数 vs 论文声称数

**铁律：** Table 1 基线数据必须与原始登记严丝合缝。

**必附样本流向图（5 分钟可完成）：**
```
总样本 n=68（随州中心医院 45 + 随县中医院 23）
  ├─ SFTSV 阳性 n=32
  │    ├─ 纳入分析 n=30 ← 论文报告这个数
  │    └─ 剔除 n=2（溶血标本，编号 SFTS-017/038）
  └─ 未知病原 n=36
       ├─ 纳入分析 n=36
       └─ 剔除 n=0
```

**硬性规定：** 论文正文必须明确写出纳入和剔除数量及原因。ELN 记录 ≥ 代码纳入 ≥ 论文声称，中间有差额必须标注原因。差一个数 → 退回重改。

### 2.4 Motivation 答辩 + Overclaim 审查

**时机：** 论文初稿完成后，组会 15 分钟陈述

**四个必答问题：**
1. 这个科学问题是真的存在，还是为了用某个技术编出来的？
2. 如果结果全部推翻重来，这个研究方向本身还成立吗？
3. 你的结论如果错了，会有人在意吗？
4. 你的结论边界在哪里？—— 模型生物上验证的，别说成人群普遍规律；相关性发现的，别说成因果机制

**因果断言标注规则：** 论文中任何声称因果关系的句子，必须标注对应的实验证据编号。如："A activates B (Fig. 3C-D, Co-IP; Fig. 4A, WB; Fig. S2, Confocal)"。无标注的因果断言 → 退回补证据或降级为相关性表述。

**判定：** PI + 课题组全员在场，至少两人提出质疑并获合理解答。PI 系统点"通过"。

### 2.5 AI 文本痕迹与浮夸词排查

**Step 1 · 机器预扫：** GPTZero 全文扫描，重点盯 Abstract 和 Discussion

**Step 2 · 关键词黑名单（可直接 Ctrl+F）：**

| 黑名单词 | 原因 |
|---|---|
| revolutionary | AI 偏好浮夸修饰，不管证据多强都不该出现在学术论文中 |
| undoubtedly | 同上 |
| without any doubt | 同上 |
| first-ever | 无法验证的绝对化声称 |
| completely novel | 同上 |
| solves / resolved | 单个研究很少能"solve"一个领域问题 |
| opens a new era | AI 偏好的空洞宏大叙事 |
| unprecedented | 无法验证 |
| paradigm shift | 空洞浮夸 |

**已移除：** `proves / proved / demonstrate` —— 多实验正交验证（WB + Co-IP + 共聚焦指向同一结论）时，使用 prove/demonstrate 是合理的，不构成 overclaim。

**Step 3 · 判定：** Abstract / Discussion 命中 ≥ 3 个黑名单词 → 自动打回降温修改。不争吵，改完再交。

### 2.6 通讯作者与投稿邮箱审计 — 防代投

**痛点：** 代投机构掌控投稿账号，与腐败编辑串通完成论文发表。

**先审后投硬性规则（整个 Workflow 的基石）：**
- **院长签字生效前，论文不得进入任何期刊的投稿系统**
- 投稿动作必须在 Phase 3 终审通过、院长签字之后才能执行
- 投稿后将投稿确认信截图（含 Manuscript ID + 投稿时间戳 + 投稿 IP）交回秘书处归档
- 若投稿时间早于院长签字时间 → 无论论文本身是否存在问题，**直接冻结 6 个月 + 全院通报**
- 这条是防所有流程被绕过的最后锁——审都没审就投了，Workflow 形同虚设

**Phase 2 投稿前强制规则：**
- 通讯作者必须使用学校统一分配的 @xxx.edu.cn 邮箱投稿
- 禁止使用 Gmail/163/QQ 等个人邮箱作为通讯邮箱
- 投稿 IP 核查：作者人在武汉，投稿 IP 却长期在境外/代写黑产活跃地区 → 红灯

### 2.7 外包实验边界 — 什么能外包、什么不能、外包了怎么审

**原则：** 实验外包在现实中不可能完全禁止（测序、预制胶、质谱等在生科院本身就是外包的），但不能让"外包"成为造假的遮羞布。

**白名单（可以外包，但必须留痕）：**

| 可外包类型 | 示例 | 必须提交的凭证 |
|---|---|---|
| 测序服务 | 全转录组、外显子组、单细胞测序 | 测序公司原始下机数据 + FastQC 报告 + 公司盖章交付单 |
| 商业化试剂/耗材 | 预制胶、商品化抗体、试剂盒 | 采购记录（货号、批次、购买日期）|
| 第三方检测 | 质谱鉴定、电镜成像、病理切片扫描 | 检测机构原始报告 + 原始数据文件 |
| 动物饲养/繁育 | 基因敲除鼠构建、动物寄养 | 动物房饲养合同 + 基因型鉴定报告 |
| 通用生信分析 | 公共数据库数据下载与预处理 | 代码 + 中间态清洗数据（同 2.2 标准）|

**黑名单（必须课题组亲自完成，不得以外包名义代做）：**
- 论文核心结论所依赖的关键实验（如 Co-IP 验证蛋白互作、Western Blot 关键条带、活体动物感染模型）
- 临床样本的采集与处理
- 原始数据的统计分析
- 论文撰写

**判定规则：**
- 论文核心实验结果来自外包 → 必须在 Methods 中明确声明 + 标注外包机构名称 + 提交外包合同/服务清单
- 属于黑名单但声称"外包"的 → **按造假处理**，外包不是挡箭牌
- 论文涉及大量外包实验且课题组无对应实验设备采购记录 → 物理穿透审查中重点关注（你连仪器都没买过，实验怎么做的？）

**交叉锁死防线（Phase 1 NAS 归档 ↔ 2.7 黑名单）：**
- Phase 3 Step 1 审查中硬性核验：凡论文涉及黑名单中的核心实验（Co-IP 关键条带、Western Blot 核心结果、活体动物感染模型、临床样本处理），必须在 1.2 节规定的学院 NAS 归档区中提取到**本院仪器生成的、带时间戳的原始底层数据**（TIFF/CZI/ND2 格式）
- 若核心实验拿不出本院仪器原始数据 → 需提供合作单位的书面证明 + 对方仪器的原始数据 + 双方合作协议
- 两者都没有 → **直接判定为违规代做**，按严重级别处置
- 逻辑：你声称在学院实验室做了 WB，NAS 里就一定有凝胶成像仪自动同步的那张原始 TIFF。没有？实验就是没做。

### 2.8 PI 胁迫违规的学生保护 — "服从指令免予追责"原则

**保护学生就是保护学院名声：耿同学事件的舆论风暴，一大半火力集中在"学院包庇导师让学生背锅"。本 Workflow 的立场：在学生和 PI 的权力不对等关系中，学生不因服从 PI 指令而承担学术不端责任——学院不袒护 PI，自然不需要让学生背锅。**

**核心困境：** 生科院最真实的学术不端场景不是"学生自己决定造假"，而是"PI 让学生造假，学生不敢拒绝"。拒绝 = 得罪导师 = 延毕 + 穿小鞋 + 差推荐信。服从 = 跟着一条船沉下去。同济案例中被解聘的"第一作者"大概率就处于这个困境。

**保护规则：**

| 场景 | 处置 |
|---|---|
| 学生能证明某项违规操作是 PI 直接书面/口头指令 | **学生免予追责**，责任完全归于发出指令的 PI |
| 学生因拒绝执行 PI 的造假指令而遭到任何形式的报复 | 触发 3.11 举报人保护机制，党委书记介入 |
| 学生被 PI 要求绕过 Phase 2/3 流程（如"这组数据不要上传 ELN""用我的 Gmail 投稿"）| 学生可向党委书记匿名举报，不受封口令限制 |

**证据标准（从学生角度可操作）：**
- 理想情况：PI 的造假指令有书面记录（微信、邮件）→ 直接作为证据
- 常见情况：PI 口头指令，无书面记录 → 学生可在事后第一时间向党委书记补录陈述（时间戳 + 录音），该陈述作为保护性证据存档，不自动触发调查
- 原则：不要求学生"当场录音导师"（这在现实中不可行且破坏师生信任），但要求在意识到指令可能违规后的 **7 日内**向党委书记补报

**配套机制：** 学生入学时签署的《学术诚信知情书》明确写入本条——让学生在被胁迫之前就知道"学院有这个渠道"。PI 年度考核中确认——"我已阅读并理解，胁迫学生造假 = 本人承担全部学术不端责任"。若学生毕业后被发现在校期间参与了 PI 指令的造假行为 → 仍适用本原则，学生学位不受追溯影响，PI 追加处分。

### 2.9 预印本（bioRxiv/Research Square）的处理

**问题：** 生科领域普遍先发预印本再投期刊。如果学生绕过 Phase 2/3 直接把论文上传 bioRxiv，算不算违反"先审后投"？

**判定：预印本也是发表。上传预印本 = 进入公共领域 = 必须经过 Phase 2 审查。**

- 预印本上传前至少完成 Phase 2（PI 签字确认的数据自查）
- 预印本上传后、正式投稿前，补完 Phase 3 终审
- 若预印本已上传但未经过任何审查 → PI 在 30 天内补走 Phase 2 流程，并将审查报告作为预印本更新版本发布
- 超过 30 天未补审 → 按绕过审查处理，论文冻结 3 个月

**名声保护逻辑：** 预印本挂在 bioRxiv 上是永久的公共记录。如果预印本里的图后来被扒出拼接，学院要是能拿出"这篇预印本在上传前已通过 Phase 2 审查"的记录——那就是审过了但当时没检出来，属于技术局限。拿不出来——就是学院完全没有管控制度，纯属失职。两句话的区别，就是名声的分水岭。

## Phase 3 · 盲审与答辩前终审

**核心理念：** 机器+秘书承担 90% 排雷，委员会只看红灯。利益相关者回避。数据冷冻留底。

### 3.1 学术诚信委员会 — 架构

**固定成员（6 人）：**
- 院长（学术委员会主任）—— 主持 + 学术终审 + 最终签字
- 学院党委书记/副书记 —— 纪律监督 + 意识形态把关 + 举报受理（党委在学术不端案件中的角色是纪律问责，不替代学术判断）
- 分管科研副院长 —— 实验设计与数据完整性
- 学院统计/生信负责人 —— 代码与统计审查（Step 1 核心执行人）
- 学术委员会秘书 —— 流程记录与档案管理
- 轮值院外专家 1 名 —— 从 20 人专家池随机抽取

**职责分工（学术 vs 纪律）：**
- 学术判断（论文能不能送审）：院长、副院长、生信负责人、院外专家 —— 4 人投票
- 纪律监督（流程合规性、举报受理、利益冲突审查）：党委书记 —— 1 人监督，不参与学术投票
- 党委书记拥有一票否决权，但否决理由必须限于流程违规或纪律问题，不得以学术观点不同为由否决

**回避制度：** PI/通讯作者为委员会成员 → 该成员必须退出本次全部审查环节。院长回避时由副院长代行主任职责，副院长也需回避时由资历最深的非利益相关委员代行。回避记录写入审查档案，对外可查。

**专家池：** 与 2-3 所兄弟院校共建 20 人池。专家不读全文，只看 Phase 2 核查报告摘要 + 红灯项，只回答"结论是否超出证据支持"一个问题。线上异步，2 日内回复。

**议事规则：** 学术投票全票通过制（4 票全部同意方可送审）。反对意见须附书面理由。学生不列席投票讨论环节。

### 3.2 终审材料清单（9 件套）

| # | 材料 | 要求 | Step 1 校验人 |
|---|---|---|---|
| 1 | 论文终稿 | PDF 含全部图表和 Supplementary | 秘书 |
| 2 | Phase 2 自查报告包 | ImageTwin/Forensically 截图 + 代码复现比对结果 + 样本流向图 + Motivation 记录 | 秘书核查完整性 |
| 3 | 原始图像路径清单 | 每张图对应 NAS 路径 + SHA-256 | 生信负责人抽查 20% |
| 4 | 代码 + 环境锁 | 最终代码 + sessionInfo()/renv.lock + 清洗后数据 | 生信负责人运行比对 |
| 5 | 样本管理台账 | ELN 记录 + 样本流向图 + Table 1 核对表 | 秘书核对数字一致性 |
| 6 | AI 文本扫描报告 | GPTZero + 黑名单自查结果 | 秘书标记红灯词 |
| 7 | PI 预审签字单 | 导师对以上 6 项逐项签字 | 秘书 |
| 8 | 投稿确认信截图 | 含 Manuscript ID + 时间戳 + 投稿 IP + 通讯邮箱 | 秘书核对 @edu.cn + IP 属地 |
| 9 | PI 经费自查报告 | PI 从财务系统自行导出《近两年测试化验加工费与版面费明细》+ 签字的《外包服务合规承诺书》 | 秘书核查是否提交，不主动调取 |

缺一件 → 退回补齐，48 小时未补 → 自动冻结本次送审。

### 3.3 终审流程 — 红绿灯分级

**Step 1 · 硬核排雷（秘书 + 生信负责人，1-2 个工作日）**

秘书负责：材料齐全性、ImageTwin 飘红是否有解释、AI 黑名单命中数、样本流向图数字自洽、投稿邮箱是否为 @edu.cn、投稿 IP 属地是否异常、PI 经费自查报告是否已提交

生信负责人负责：代码独立运行 + 机器比对统计量差异率、随机抽查 20% NAS 路径哈希一致性

**产出：红绿灯报告（含论文工厂维度）**

| 灯 | 条件 | 处置 |
|---|---|---|
| 🟢 绿灯 | 图片无飘红 · 代码统计量一致 · 样本数字咬合 · 黑名单词 ≤2 · 投稿邮箱合规 · 投稿 IP 属地正常 · 无异常财务支出 | 快速通道 |
| 🟡 黄灯 | 存在已解释的飘红 / 轻微数字偏差但可合理解释 / 投稿 IP 属地有波动但可解释 | 委员关注 |
| 🔴 红灯 | 未解释的拼接 / 代码 p 值对不上 / 样本数不一致 / 黑名单词 ≥3 / 非 @edu.cn 邮箱投稿 / 投稿 IP 长期在境外或代写黑产地区 / 命中财务可疑交易 | 触发实质性审查 |

**Step 2 · 分级审查：**
- 全绿灯 → 4 位学术委员传阅报告 + 审视 Discussion Overclaim → 批量签字，党委书记确认无流程违规
- 黄灯/红灯 + 随机抽查 10% → 全体委员启动完整闭门审查 + 院外专家回复

**委员审查表（一页纸三个勾）：**
1. 是否发现无法解释的数据异常？□是 □否
2. 论文结论是否超出证据支持范围？□是 □否
3. 是否同意送审？□同意 □不同意（须注明具体问题）

**Step 3 · 质询与裁决（红灯触发）：**
- 委员会召集学生 + PI 当面质询
- 学生有权解释、补充材料、修正表述
- 质询后重新投票
- 仍不通过 → 冻结送审 6 个月，PI 监督整改
- 明确造假证据 → 直接升级校级学术道德委员会

### 3.4 分级处置

| 等级 | 场景 | 处置 |
|---|---|---|
| 🟡 轻微 | 个别绝对化表述未修正、黑名单词略超标但语义合理、投稿 IP 属地有波动但可解释 | 48h 修改 → 复核 → 通过 |
| 🟠 中等 | 代码无法复现核心结果、多图原图缺失、样本量多处不一致、试剂采购记录与论文实验量不匹配 | 冻结 6 个月 → PI 监督整改 → 重新走全流程 |
| 🔴 严重 | 明确图像拼接、数据篡改、样本量蓄意造假、物理样本缺失、投稿 IP 在代写黑产活跃地区、财务记录显示购买论文 | 上报校级 → 学术不端调查 → 院长出具书面说明 |
| ⚫ 论文工厂 | 全绿灯但物理穿透审查发现实物/凭证全面缺失 + 财务记录显示大额异常支付至可疑公司 | 直接上报校级 + 通报公安机关（涉嫌科研经费诈骗）|

### 3.4.1 学生申诉机制 — 论文被冻结后的救济通道

**问题：** 3.4 分级处置决定了论文的命运，但如果学生认为判定不公（如机器误报、PI 预审疏漏但学生本人不知情），必须有独立于原委员会的救济通道。**申诉机制不仅是学生的权利保障，更是学院自证"审查不是走过场"的制度证据——有申诉、有复议、有纠错，说明审查流程是活的，不是橡皮图章。**

**申诉路径（三级递进）：**

| 层级 | 受理人 | 触发条件 | 时限 |
|---|---|---|---|
| 一级 · 委员会复议 | 原审查委员会（回避原反对委员，替换为未参与审查的资深委员）| 学生提供新证据或指出审查程序错误 | 收到申诉后 5 个工作日 |
| 二级 · 院长复核 | 院长 + 院外专家 2 名（从专家池随机抽取，不重合原审查专家）| 学生对一级复议结果不服 | 收到申诉后 10 个工作日 |
| 三级 · 校级申诉 | 校级学术道德委员会 | 学生对二级复核结果不服，或申诉涉及 PI 本人且院级存在系统性利益冲突 | 按校级规定时限 |

**申诉期间论文状态：** 论文维持冻结，但学生可申请"论文剥离"——若论文被冻结的原因与学生的个人学位论文直接相关，且学生本人未被指控造假，学生可申请将论文数据剥离用于学位论文，由独立答辩委员会单独评审。

**防止申诉权被滥用：** 同一论文同一问题仅可申诉一次（一级 + 二级）。若新增实质性证据，可重新启动一级申诉。恶意申诉（反复申诉无新证据）→ 维持原判并记入申诉记录。

### 3.4.2 PI 作为被调查对象的分支流程

**触发条件：** 造假嫌疑指向 PI 本人（而非学生），或 PI 是论文的通讯作者/第一作者且红灯项涉及核心实验数据。

**原流程的问题：** 3.4 分级处置默认"PI 监督整改"。但如果造假者就是 PI 本人，"PI 监督整改"完全不成立——同济大学院长案例即是如此。

**分支流程：**
1. 委员会中若 PI 本人为成员 → 强制回避（已有规则）
2. 一旦红灯触发 Step 3 质询，且问题指向 PI → 党委书记自动升级为调查主持人（替代院长，因为院长可能是 PI 的合作者/同僚）
3. 调查期间，该 PI 课题组全部在审论文自动冻结
4. 若质询后认定 PI 存在造假嫌疑 → 不经过学院层面裁决，**直接上报校级学术道德委员会**，由校级独立调查
5. 党委书记在 48 小时内将初步调查记录和回避情况书面报告校纪委和学术道德委员会

**为什么需要这个分支：** 院级委员会成员的学术关系网（同僚、师兄弟、合作者）决定了院级自己查自己的 PI 不现实。PI 层面的问题必须上升一级，由校级独立调查，院级只负责拦截和上报。

### 3.5 院长签字背书

**签字前确认：** 4 位学术委员均投票"同意"（回避者不计入）、党委书记无流程合规异议、全部材料已归档、PI 预审签字单完整

**标准化声明：**
> "经学院学术委员会审查，该论文所涉实验数据、分析代码及原始记录已通过全流程核查。本委员会对论文中数据的真实性和分析的可重复性承担审查责任。如论文发表后出现学术不端指控，本审查记录将作为调查依据对外提供。"

签字的意义不是"保证论文完美"，而是"流程走完了，记录在案了，出了事查得清楚"。

### 3.6 数据冷冻

**触发时机：** 院长签字生效后立刻执行。

**冷冻内容：** 9 项材料全量打包为不可修改 Zip 压缩包。

**技术实现（三选一）：**
- A. NAS 冷存储（零成本）：Zip → SHA-256 → 独立只读分区
- B. 区块链存证（低成本）：仅哈希值上链（如蚂蚁链），原文件存 NAS
- C. 云温备份：S3/OSS + WORM 锁，合规保留 10 年

**防什么：**
- 五年后举报 → 调出压缩包 → SHA-256 一致 → 原图说话
- 原图完好 → 对外公布，举报不攻自破
- 确实造假 → 压缩包本身是追责证据链 → 学院管理层因"审查流程完整+档案齐全"而免责

### 3.7 物理实体与凭证穿透审查 — 防论文工厂

**核心逻辑：** 论文工厂能编完美数据，但变不出物理样本、动物、试剂发票。这是唯一能抓住"高级黑产"的维度。

**触发条件：** 从全绿灯论文中随机抽取 10%，执行穿透审查。

**审查项目：**

**① 生物样本物理核实：**
- 论文声称使用临床患者样本 → 实地查看对应编号的血清/核酸冻存管是否物理存在
- 论文声称使用动物模型 → 调取动物房饲养记录、伦理审批原件、动物采购凭证
- 论文声称使用特定细胞系 → 核对细胞库购买记录/赠予协议 + 液氮罐冻存位置
- 判定：实物缺失 → 直接启动学术不端调查，不需要其他证据

**灭失物证的替代凭据（时效性补丁）：**
活体实验结束后动物已被处理、组织样本已消耗殆尽是正常情况，不因此判定违规。替代核查路径：
- 活体动物已处理 → 审查动物房出具的《动物无害化处理登记表》（动物房必有此签字记录，含处理日期、数量、方法）
- 组织/RNA/DNA 样本已消耗 → 审查测序公司发回的原始下机数据报告 + 质检单（FastQC 报告、公司盖章的交付确认单）
- 血清/冻存管仍在 → 必须物理存在，这是长期保存的，不能说"消耗了"
- 原则：**可消耗样本查阅销毁/消费凭证，应长期保存样本必须实物在场**

**② 试剂耗材与测序费用比对：**
- 论文声称提取 n 个样本 RNA 并做全转录组测序 → 核对课题组财务账上对应的 RNA 提取试剂盒 + 测序服务采购记录
- 论文声称使用某种抗体做 WB/Co-IP → 核对抗体采购记录（货号、购买日期、数量）
- 判定：论文声称的实验消耗与采购记录严重不符 → 红灯，启动调查

**③ 合作单位交叉验证：**
- 论文涉及多中心临床样本 → 联系合作医院/机构，核实样本提供是否真实
- 论文涉及国际合作 → 核对合作方是否知情且实际参与
- 判定：合作方不知情或否认提供样本 → 严重造假，上报校级

**执行细则：**
- 秘书提前 48 小时通知（不允许临时收拾，48 小时不够"变出"半年份的动物饲养记录）
- PI 陪同核查，但由委员会成员亲自查看实物和原始记录
- 核查结果拍照存档，附入论文终审档案

### 3.8 财务报销异常拦截 — 拦截买卖交易

**核心逻辑：** 买卖论文的大额资金流动，必然经过财务系统。但学院秘书无权直接调取 PI 财务记录——绕过 PI 查账会引发集体抵制，且违反财务隔离规定。

**改为举证责任倒置：PI 自行导出 + 签字承诺。**

**Phase 3 材料清单第 9 项：PI 经费自查报告**

包含两部分：
1. **财务明细导出：** PI 登录大学财务系统，自行导出《近两年测试化验加工费与版面费明细》，筛选科目：测试化验加工费、版面费、文献检索费、润色翻译费
2. **外包服务合规承诺书（PI 签字）：**
   > "本论文所有测序、生信分析、语言润色等外包服务均已如实申报。论文撰写、数据分析、投稿均由课题组独立完成，未通过任何第三方机构进行代写、代投或买卖。"

**秘书仅检查是否提交，不审核内容。** 委员会在 Step 2 审查时，若明细中存在可疑支出（不知名公司 + 论文服务费 + 单笔 >5000 元 + 投稿前后 3 个月），可要求 PI 口头解释。无法解释 → 红灯。

**为什么这样做可行：**
- 让 PI 自己点下载，不触发财务隔离墙，合规
- 签字承诺书把法律责任压实给签字人
- 真正买论文的人不敢签——签了就是书面伪证，不签就是自曝
- 不增加 PI 实质性负担（导出明细 + 签字不超过 5 分钟）

### 3.9 论文分类与差异化审查

**问题：** 综述、Meta 分析、纯生信挖掘（如 TCGA 数据挖掘）没有湿实验。当前的物理穿透审查和样本溯源对其不适用。一刀切会导致这类论文"自动免检"或"被无意义流程卡住"。

**论文分类（Phase 2 时由 PI 标注）：**

| 类型 | 定义 | 差异化的审查要求 |
|---|---|---|
| A 类 · 原始实验论文 | 含课题组自行产生的湿实验数据 | 走完整 9 项材料 + 物理穿透审查适用 |
| B 类 · 公共数据挖掘 | 基于 TCGA/GEO 等公共数据库的分析 | 免 2.3 样本溯源、免 3.7 物理穿透。强化 2.2 代码复现 + 2.4 Overclaim 审查。额外要求：论文必须声明数据来源 accession number + 下载日期 |
| C 类 · 综述/Meta 分析 | 文献综述或已发表数据的合并分析 | 免 2.1 图像自查、免 2.2 代码复现、免 2.3 样本溯源、免 3.7 物理穿透。强化 2.4 Motivation + Overclaim 审查 + 2.5 AI 文本检测。额外要求：检索策略和纳入/排除标准必须可复现 |
| D 类 · 方法学/工具论文 | 新算法、新软件、新实验方法 | 按是否有实验验证数据归入 A 类或 B 类 |

**分类核查：** 委员会在 Step 2 有权质疑 PI 的分类标注。若 A 类论文在物理穿透审查中无法提供实物凭证却声称"样本已消耗"且无替代凭据 → 降至 D 类并要求修改论文中涉及实验部分的声称强度。

### 3.10 论文被拒后重新投稿 — 快速复审通道

**问题：** 通过全流程的论文可能被期刊拒稿，改投其他期刊时若重走全流程，毕业生等不起。

**快速复审规则：**

| 变更程度 | 流程要求 |
|---|---|
| 仅修改格式/投稿期刊，数据和结论未变 | 提交新的投稿确认信 → 秘书更新归档 → 无需委员会重审。原冷冻包保持有效。 |
| 修改了个别图表、补充了少量实验（< 20% 图表面板变更） | PI 提交变更说明 + 新增数据的 Phase 2 自查报告 → 秘书 + 生信负责人审新增部分 → 原投票委员书面确认无误 → 院长更新签字 |
| 大幅修改、新增关键实验、核心结论变化 | 视为新论文，重走 Phase 2 + 3 全流程 |

**冷冻包管理：** 每次重新投稿后，新的投稿确认信 + 变更材料追加入原冷冻包，生成新哈希值。所有版本链式关联，保留完整演变轨迹。

### 3.11 内部举报人保护机制

**内部举报人是学院最早的风控信号。如果内部人不敢说话，造假潜伏多年后由外部耿同学们引爆——那时学院失去的不只是一篇论文，而是对自家 PI 的全部控制权叙事。建立内部举报通道不是为了"鼓励举报"，而是为了确保问题在学院内部被消化处理，而不是在抖音上被解决。**

**多通道举报体系：**

| 举报通道 | 受理人 | 适用场景 | 保护措施 |
|---|---|---|---|
| 导师/PI 直接沟通 | PI | 日常实验记录疑点、数据异常 | 课题组内部解决 |
| 学院学术委员会实名举报 | 党委书记（唯一受理人）| PI 涉嫌造假、或举报人不敢通过 PI 渠道 | 党委书记单独受理，不经过院长和副院长。实名保护，不得向被举报人透露举报人身份 |
| 校级学术道德委员会匿名举报 | 校纪委/学术道德委员会 | 学院层面受理人可能与被举报人存在利益关系 | 独立于学院的第三方通道 |

**保护规则：**
- 举报人不得因实名举报受到任何形式的打击报复——延毕、扣发补助、调离课题组、论文署名除名。若被报复 → 党委书记直接介入，暂停 PI 招生资格直至调查结束
- 举报经查属实 → 举报人获得诚信记录书面认可；恶意诬告 → 诬告者承担学术不端同等后果
- **隐性报复防护：** PI 的隐性报复（差的推荐信、排斥出核心项目、学术圈散布负面评价）更难证明。若举报人需要推荐信 → 由党委书记或院长以学院名义出具官方推荐信替代 PI 的个人推荐信；若被排斥出核心项目 → 学院协调其他课题组提供过渡岗位；若发现 PI 散布针对举报人的负面评价 → 视为学术不端加重情节

**学生毕业资格剥离保障：**
- 若举报人为在读研究生且被举报导师为其指导教师 → 党委书记受理举报的同时启动毕业保障程序：协助更换导师或组建独立答辩委员会
- 原则：**学术不端案件的调查周期不得成为拖延举报人正常毕业的理由**
- 举报经查属实且导师被认定学术不端 → 举报人在该导师指导下已发表的受影响论文，不纳入举报人的学位申请成果评定，也不因此撤销举报人已获得的学位

**匿名举报的处理：** 匿名举报受理门槛高于实名——需提供可验证的具体证据（如图片编号、日期、数据异常点），仅凭"感觉有问题"的匿名举报不启动调查。

### 3.12 与校级学术委员会的对接

**问题：** 学校层面已有学术评审委员会/学术道德委员会。学院 Workflow 不能与校级机构重叠或冲突。

**层级分工：**

| 层级 | 职责 | 权限 |
|---|---|---|
| **学院学术诚信委员会**（本 Workflow 主体）| 论文送审前审查、日常数据管理监督、轻微/中等问题处置、内部举报受理 | 冻结/放行论文送审、要求整改、上报严重案件 |
| **校级学术道德委员会** | 学术不端案件的正式调查与裁定、跨学院纠纷、PI 级别违规 | 启动正式调查、做出学术不端认定、建议行政处分 |
| **校纪委/监察处** | 涉及科研经费滥用、诈骗、利益输送等违纪违法问题 | 纪律审查、行政处分、移送司法机关 |

**上报触发条件（学院 → 校级）：**
- 学院调查确认或高度怀疑存在数据造假/论文工厂
- 造假行为涉及 PI 本人
- 涉嫌科研经费滥用（与 3.8 联动）
- 举报人指控 PI 造假且提供了初步可验证证据
- 同一 PI 课题组在 2 年内有 2 篇及以上论文触发红灯

**上报材料：** 学院提交全套审查档案（9 项材料 + 红绿灯报告 + 委员会投票记录 + 质询记录），校级在此基础之上独立调查，不再重复做学院已完成的数据比对工作。

**校级审查后的反馈：** 校级调查结论返回学院，存入学术诚信档案。若认定无学术不端 → 学院恢复论文送审资格。若认定学术不端 → 学院执行校级处分决定 + 全院通报 + 院长在教师大会上做说明。

### 3.13 多作者论文的责任分配 — 不搞连坐

**问题：** 一篇论文通常有多个作者（第一作者、共同第一作者、通讯作者、参与作者），来自不同课题组甚至不同机构。若某一作者负责的部分被认定造假，其他作者是否因此连带受罚？

**原则：不搞连坐。责任精确到造假的执行者和负有审查义务的通讯作者。**

**责任分配矩阵：**

| 角色 | 对论文数据的责任 | 造假发生时的处置 |
|---|---|---|
| **通讯作者（PI）** | 对全文数据的真实性和审查流程完整性负总责 | 无论造假发生在哪一部分，通讯作者均承担管理责任（至少为 🟠 中等） |
| **第一作者/共同第一作者** | 对自己直接产生和提交的实验数据负责 | 仅对自己名下的造假数据承担责任。若他人负责的部分造假且第一作者不知情 → 不承担造假责任 |
| **参与作者** | 对自己署名认可的数据负责 | 若能证明本人仅提供了试剂/方法/样本而未参与数据造假 → 免予追责。但论文署名即表示对全文数据的知情同意 |
| **跨机构作者** | 按机构各自审查 | 本院 Workflow 仅对本院作者强制。院外作者的问题通过 3.12 校级对接 + 函告对方单位处理 |

**处置细则：**
- 论文被判定学术不端后，仅撤销造假责任人（执行者 + 负有审查义务的通讯作者）在该论文中的学术贡献认定
- 无责作者的学位、职称、学术贡献不受该论文的影响——包括：共同第一作者中无责方仍可将其用于学位申请和职称评审
- 若论文中有多位作者来自本院不同课题组 → 数据冷冻时，各课题组各自归档本组提交的数据部分，形成"拼接式归档"——出了事能追溯到具体谁的数据是假的
- 若无法区分造假数据的归属（如生信分析代码由多人共同维护且无法追溯到具体操作人）→ 通讯作者 + 该分析部分的所有署名分析人员共同承担责任

**"拼接式归档"操作规则：**
- 多课题组合作的论文，Phase 2 提交材料时，各 PI 分别签署本组数据的预审单
- 冷冻包内按课题组分别打包，标注各组的原始数据边界
- 事后追溯时：打开冷冻包 → 定位到造假数据所属的子包 → 追责对应 PI 和第一作者 → 不牵连其他子包的负责人

## Phase 4 · 舆情应急响应与切割机制

**核心理念：** 不捂盖子，不盲目护短；用冷冻证据说话；学院管理层第一时间与造假者物理切割。

### 4.1 舆情触发与 24 小时内网静默

**触发条件：** PubPeer 出现多条负面质疑、知乎/微博/抖音等平台出现点名本院学者的涉嫌造假实名举报，且引发一定关注。

**操作动作：**

**立刻冻结对外发声：**
- 党委书记第一时间下达封口令：严禁涉事 PI、课题组学生在任何网络平台私自回应、对线或发布所谓"自证"文章
- 封口令边界：学生配合学院调查组如实陈述不在此限——防止被外界或当事人理解为"压制举报"
- 封口令时效：持续至学院官方声明发布，为期不超过 72 小时

**接管处置权：**
- 涉事 PI 丧失对该事件的对外解释权
- 所有回应（包括官方声明、媒体答询、平台回复）必须由学院统一拟定
- 学院指定一名发言人（建议由党委书记或分管行政副院长担任，不宜由涉事 PI 的同课题组同事担任）

### 4.2 "开盲盒"：调取冷冻档案（黄金 4 小时）

**痛点：** 舆情爆发时，领导第一反应去找涉事 PI 问"你到底造假没"，PI 会避重就轻甚至撒谎。同济事件中，校方初期回应含糊正是因为手上没证据。

**核心原则：不要先问人，先问系统。**

**操作动作：**

**双人解封：**
- 院长 + 党委书记双人同时在场，才能从冷库解封涉事论文的冷冻 Zip 压缩包
- 双钥匙机制：类似银行保险柜，任何一人单独无法调取或删除归档
- 解封操作记录写入系统日志，对外可查（证明档案未被篡改）

**按图索骥：**
- 拿着网上举报者指出的疑点（如"图 3C 涉嫌拼接"），直接去冷冻包里找对应的原始 TIFF/CZI 哈希文件和代码
- 生信负责人同步验证哈希值是否与归档时一致（证明此后未被替换）

**闭门定性（4 小时内）：**
- 学术诚信委员会（回避涉事 PI）基于冷冻档案形成内部初步结论：
  - 数据没问题、哈希一致 → 恶意举报/误伤
  - 当年审查漏过、档案中有异常但未被当时的工具检出 → 技术盲区
  - PI 伪造了提交给审查系统的材料、实际投稿用了另一套数据 → PI 绕过系统
  - 冷冻档案缺失、论文从未通过 Phase 3 → PI 绕过了整个审查流程

### 4.3 危机公关回应策略（分级响应）

拿到冷冻包的底牌后，学院回应可以做到有的放矢。

**情景 A：底牌过硬（恶意举报/误伤）**

回应策略：**强硬反击，铁证说话。**
- 学院直接发布官方声明，公布当年冷冻档案中该图片的原始版本、无修改哈希值以及仪器生成的时间戳
- 有条件时可邀请第三方（如 PubPeer 版主或同行期刊编辑）验证原始数据
- 话术示例："经调取本院学术诚信档案，该论文在送审前已通过全流程数据核验。现公布涉事图片的原始仪器文件及 SHA-256 哈希值，供学术界公开验证。"
- 效果：用铁证迅速平息舆论，不做无谓争吵

**情景 B：确实存在造假，但属于当年检测技术盲区（如新型 AI 生成图）**

回应策略：**坦承局限，启动追责。**
- 不掩饰、不狡辩——"当年的工具确实没检出来"比"我们查过了没问题"更具公信力
- 话术示例："经调取本院存证档案，当年审查系统未发现异常。但根据最新举报线索人工复核，确认该论文存在学术不端行为。学院已暂停涉事学者职务，上报校级学术道德委员会启动正式调查。学院将在一个月内升级检测工具以覆盖此类新型造假手段。"
- 效果：表明学院尽职了但技术有局限，不属于管理失职——审查流程本身没有错，错在造假者手段升级了

**情景 C：PI 绕过系统作案（如代投、买卖实体样本）**

回应策略：**迅速切割，制度自证。**
- 声明直接点出涉事者具体违反了 Workflow 的哪一条铁律，用详实的管理制度反证学院管控有效
- 话术示例："经查，涉事人员通过私自篡改 1.4 节规定的样本流向台账、使用非学校邮箱规避 2.6 节投稿审计，蓄意绕过了学院学术诚信审查体系。该行为属于个人蓄意破坏学院管理制度，学院已将其除名并移交司法机关。"
- 效果：该学者是制度的破坏者，学院是制度的建立者和维护者——切割清晰

**情景 D：冷冻档案缺失（论文从未通过审查）**

回应策略：**承认流程漏洞，启动追溯。**
- 这是最坏情况——论文从未经过 Phase 3，意味着审查流程被绕过了
- 话术示例："经查，涉事论文未按学院规定提交学术诚信审查，系涉事人员个人违规发表。学院已启动调查：为何该论文被绕过审查流程，以及是否存在其他未送审论文。涉事课题组近三年全部论文即日起进入追溯审查。"
- 效果：承认管理漏洞但表明正在补上，同时暗示"绕过审查"本身就是严重违规

### 4.4 舆情善后与制度补丁

**无差别回溯审查：**
- 无论舆情是否属实，涉事课题组近三年的所有论文必须重新走一遍全流程审查
- 不论文是已发表、在审还是已接收——冷冻档案中的全做一次哈希比对，确保投稿版本与审查版本一致
- 目的：不是"有罪推定"，而是向公众证明学院对涉事课题组已有完整覆盖

**制度补丁（一个月内发布 Workflow v2.0）：**
- 复盘当年 Phase 2（预审）和 Phase 3（终审）为何没有拦住该问题
- 若属于工具盲区 → 升级检测工具（如加入 AI 生成图像检测模块）
- 若属于流程绕过 → 加固绕过截断机制（如强制关联投稿系统与院内审查系统）
- 若属于人为违规 → 加强 PI 合规承诺的法律效力（如引入校级层面的违规追责条款）
- 更新后的 Workflow v2.0 在全院教师大会上发布，由院长亲自说明改动原因

**全院教师大会复盘报告：**
- 舆情事件结案后，院长在教师大会上做全流程复盘
- 不回避、不美化——该公布的问题公布，该追究的责任追究
- 核心信息："出了事学院担得起，因为有档案。绕过的代价比造假的代价还大。"
- 效果：同济事件后，其他学院的 PI 之所以紧张，就是因为看到了免职的真实后果。复盘报告让全体 PI 亲眼看到违规的代价——不需要发文件强调"学术诚信重要性"，看一次案例胜过一百份通知

### 4.5 期刊调查与撤稿的静默响应（非舆情场景）

**场景：** 期刊编辑部或 PubPeer 上有零散质疑，但没有上热搜。期刊联系学院要求配合调查。这种情况远比 4.1 的舆情爆炸更常见，但没有公众压力，学院最容易被"内部消化"的惯性裹挟。

**名声保护逻辑：** 舆情爆炸时，公众盯着，学院被迫回应。但没有舆情时，学院反而更容易犯错——悄悄放过去，以为没事。等几年后被耿同学们翻出来，学院当年"知情但未处理"就是最大的名声杀手。**期刊调查的应对策略应该和舆情爆炸完全一致：调档案、拿证据、不私下交易。**

**响应流程：**

1. 收到期刊调查通知 → 秘书即刻通知院长 + 党委书记，不经过涉事 PI 转发
2. 4.2 双人解封流程启动，调取涉事论文冷冻档案
3. 7 个工作日内，学院向期刊提交正式回复：
   - 冷冻档案中对应数据无异常 → 附原始数据和哈希值，支持论文数据真实性
   - 冷冻档案中发现的异常 → 主动撤回论文，不等待期刊裁决
   - 冷冻档案缺失（论文未经过审查）→ 如实告知期刊"本院无法确认该论文数据真实性"+ 内部启动调查为何绕过审查
4. 期刊做出撤稿决定 → 学院在官网发布简短声明（不与期刊结论对抗、不替涉事 PI 辩解）
5. 若期刊决定不撤稿但学院认为数据有问题 → 学院仍可单方面在教师大会上通报 + 限制该 PI 的招生/投稿资格

**底线原则：宁在期刊面前丢一篇论文，不在公众面前丢整个学院的名声。** 主动撤稿是可控的学术纠错，舆情爆炸后的被动撤稿是名声灾难。

设计完成后，选取已知问题的公开论文，按 Workflow 逐场景验证。

**场景 A · 数据篡改（如同济大学涉事《Nature》论文）：**
1. Phase 1：检查该论文的实验数据是否有 ELN 记录、原始图像是否有哈希存档、代码是否可追溯 —— **预期：全部缺失，Phase 1 防线即暴露问题**
2. Phase 2：用 Forensically/ImageTwin 扫描该论文公开的图片 —— **预期：Western Blot 条带拼接/复用被自动标记红灯**
3. Phase 3：模拟委员会审查 —— **预期：红灯触发实质性审查，论文无法通过终审**

**场景 B · 论文工厂（假设场景）：**
1. 论文机器扫描全绿灯、代码完美复现、图片无拼接
2. 随机抽查 10% 触发 3.7 物理穿透审查 → 实地查看临床样本冻存管，发现对应编号的样本不存在
3. 3.8 财务审查 → PI 经费自查报告显示投稿前 2 个月向"XX 生物科技有限公司"支付 30000 元"数据分析服务费"
4. PI 无法提供外包服务清单 → ⚫ 论文工厂级别，上报校级 + 通报公安机关

**场景 C · PI 本人造假（如同济院长案例）：**
1. 论文通讯作者为院长本人 → 3.1 回避制度生效，院长退出审查
2. 红灯触发 → 3.4.2 PI 分支流程启动，党委书记主持调查
3. 确认 PI 存在造假嫌疑 → 直接上报校级学术道德委员会，不经过学院自行裁定
4. 该 PI 课题组全部在审论文自动冻结

**场景 D · 内部举报（如学生发现 PI 删数据）：**
1. 学生通过 3.11 实名通道向党委书记举报
2. 党委书记单独受理，核查 Phase 1 ELN/NAS 记录
3. 确认 ELN 记录与 PI 提交的论文数据不一致 → 启动 3.4.2 PI 调查流程
4. 举报人信息全程保密，不受打击报复

**场景 E · PI 胁迫学生造假（如同济第一作者困境）：**
1. PI 口头指令学生"这组数据不要上传 ELN，直接用我给的图替代 WB 条带"
2. 学生在意识到指令违规后 7 日内，向党委书记补报陈述 → 启动 2.8 保护机制
3. 学生免予追责，党委书记秘密启动对 PI 的调查
4. 学生在调查期间申请 3.11 毕业资格剥离 → 协调更换导师或独立答辩
5. 若毕业后追查到此论文造假 → 学生适用 2.8 保护原则，学位不受追溯影响，PI 追加处分

**场景 F · 多作者论文中一人造假，其他人被牵连：**
1. 论文有三位共同第一作者（本院 A、B + 外校 C），通讯作者为 PI
2. 冷冻包为拼接式归档（3.13），三个课题组各归档本组数据子包
3. 事后举报指向 Fig. 3C 拼接 → 定位到子包-课题组 A → 追责 PI + 第一作者 A
4. 第一作者 B、外校 C 不承担造假责任，学位和职称不受影响
5. 通讯作者 PI 因管理责任承担 🟠 中等处置

**场景 G · 预印本绕过审查：**
1. 学生在 bioRxiv 上传了未经 Phase 2 审查的预印本
2. 学院例行抽查中发现该预印本无审查记录 → 通知 PI 在 30 天内补走 Phase 2
3. PI 补审完成 → 审查报告作为预印本更新版本发布
4. 30 天未补 → 论文冻结 3 个月
5. 若预印本后来被发现造假 → 学院可以出示"发现问题后立即启动补审"的时间线，证明学院管控有效

**场景 H · 期刊静默撤稿调查：**
1. 期刊编辑部邮件联系学院："贵院某论文 Fig. 2B 被读者质疑数据异常，请配合调查"
2. 秘书不转发给涉事 PI，直接通知院长 + 党委书记
3. 双人解封冷冻档案 → 调取 Fig. 2B 的原始 TIFF 和哈希值
4. 档案中原始数据与论文一致 → 学院 7 日内向期刊提交原始数据，支持论文
5. 档案中发现原始数据与论文不符 → 学院主动申请撤稿，不等期刊强制撤稿
6. 若冷冻档案缺失 → 如实告知期刊"本院无法确认"，同时内部启动绕过审查调查
